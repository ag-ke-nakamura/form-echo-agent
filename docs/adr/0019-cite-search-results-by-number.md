# 検索結果は URL ではなく出典番号で指させる

- **Status**: accepted

## 決定

経路候補が根拠にした検索結果を、**AI が書いた URL ではなく、Runtime が振った出典番号**
（`citation_number`）で指させる。`web_search` はモデルへ返す結果1件ごとに1始まりの番号を
付け、応答の `citations` は同じ並びで運ばれる。画面はその番号で出典の一覧を引き、内訳に
「出典1」と出す。

## なぜ

候補ごとに根拠のページが要る理由は #174 にある — 「1円でも安い経路を選んだ」を職員が
検算できるのは、候補と根拠のページが対になっているときだけで、応答全体の `sources` では
どの候補の運賃がどのページの額なのかを言えない。

問題は**その値を誰が書くか**だった。URL をモデルに書かせると、写し間違い・別経路の URL の
合成（クエリを書き換えて作る）・表記の揺れ（クエリの並び順、末尾のスラッシュ、日本語の
percent-encoding）が起きる。**書かれた URL が本当に取得したページかは、取得した出典と
突き合わせないと言えない**が、その突き合わせは文字列一致なので、上の揺れをどこまで正規化で
吸収するかという答えの無い調整を抱え込む。正規化の複製は画面と BFF に2つでき、Runtime にも
置けば3つになる。

番号にすると、モデルは**渡されたものの中から選ぶ**しかない。写し間違いという失敗モードが
構造的に消え、正規化も要らない。これは ADR-0005 が候補日程で採った「識別子は発番側が持ち、
AI は自分では作らない」の適用先を、フロントエンドから Runtime へ広げたものである。

## 結果

- **番号は1つの応答の中でしか意味を持たない。** URL は単体で自己完結しているが、番号は
  `citations` と対でしか読めない。内訳の行を単体で他所へ写すと参照先が失われる
- **番号の並びを決めるのは `toCitations` 1箇所。** モデルへ渡す番号と応答の `citations` が
  同じ関数から採られている必要がある（ずれると、候補が別のページを指す）
- **範囲外の番号で応答を捨てない。** 画面がその候補の行を「確認できませんでした」と出し、
  Runtime が `log.warn` に残す。番号1つのために日付・目的・同行者・経路・運賃まで失うのは
  釣り合わない（#174 の議論）
- 出典の一覧に番号を出す必要がある。内訳が「出典2」と言うので、番号が無いと職員が
  どれを押せばよいか分からない
