## Repository layout

This repo is an AWS Bedrock AgentCore project (`FormEcho`) plus two independent frontend experiments that are not yet wired into `agentcore/agentcore.json`:

- `agentcore/` — declarative AgentCore project config (`agentcore.json`, `aws-targets.json`) and the generated CDK (`agentcore/cdk/`). Source of truth for what's deployed; see `@AGENTS.md` above for the full schema and CLI reference.
- `app/FormEchoAgent/` — the deployed agent runtime referenced by `agentcore.json` (`runtimes[0]`). TypeScript, built on the Strands SDK (`@strands-agents/sdk`) and `bedrock-agentcore`. Entry point `main.ts`; `agentcore dev` runs it locally via `tsx watch`, `agentcore deploy` ships it. Not a standalone Node app — always operate on it through the `agentcore` CLI (see AGENTS.md), not `npm run dev`/`npm start` directly, unless debugging the process in isolation.
- `hono-app/` — standalone Hono scaffold, own `CLAUDE.md`. Dependencies are managed by **pnpm** (`pnpm-lock.yaml`); the `dev` script alone runs on Bun. Not referenced anywhere in `agentcore.json`.
- `nextjs-app/` — standalone Next.js 16 + pnpm scaffold, own `CLAUDE.md` (`@AGENTS.md`, auto-generated by `next dev` — do not hand-edit `nextjs-app/AGENTS.md`). Not referenced anywhere in `agentcore.json`.

When a task is scoped to one of `hono-app/` or `nextjs-app/`, that directory's own `CLAUDE.md` takes precedence for commands/architecture; this file only covers the workspace as a whole and the AgentCore project.

## 言語方針 (Language Policy)

本プロジェクトは**日本語を基本言語**として運用します。

### 文書・コメントの言語

- **Git コミットメッセージ**: 日本語で簡潔に（例: `FormEchoAgent: メモリー戦略を SEMANTIC に変更`)
- **ADR・仕様書**: スキルの指定フォーマット（domain-modeling, to-spec 等）に従い、**内容は日本語**で記述
- **コードコメント**: 複雑なロジック・非自明な制約は日本語で記述（WHY を重視、WHAT は不要）
- **Markdown ドキュメント**: README, 設計ドキュメント、手順書は日本語

### スキルのフォーマット継承

- `domain-modeling` → ADR-FORMAT.md, CONTEXT-FORMAT.md に従う ← **記述言語は日本語**
- `to-spec` → SPEC テンプレートに従う ← **記述言語は日本語**
- その他スキル → 各スキルのガイドラインに従う ← **記述言語は日本語**

### 例外

- 生成されたファイル（CDK コード、`agentcore export` 出力）は編集しない
- 外部ライブラリの API 名・定数は英語のまま
- `nextjs-app/AGENTS.md` は `next dev` が自動生成するため手編集不可

### 参考

- 他チームメンバーも同じポリシーに従う（CLAUDE.md がソース・オブ・トゥルース）
- 各スキルがテンプレートを提供する場合、それに従いながら日本語で記述する

## Harness guardrails

`.claude/settings.json` で以下を強制しています。ブロックされた場合は回避を試みず、対象と理由をユーザーに提示してください。

- `permissions.deny`: 秘密ファイル（`.env*`, `*.pem`, `~/.aws/**`, `~/.ssh/**`）の読み取り、force push、`aws * delete-*`、IaC の destroy 系
- `permissions.ask`: `agentcore deploy` / `cdk deploy`（毎回確認）
- `.claude/hooks/guard-destructive-command.py`（PreToolUse）: `rm -rf` は再生成可能なパス（`node_modules`, `dist`, `build`, `.next`, `coverage` 等）のみ許可。それ以外は拒否
- `--dangerously-skip-permissions` は `disableBypassPermissionsMode` により無効化済み

固定パターンは `permissions.deny` に置き、フックには宣言的に書けないもの（`rm -rf` のアローリスト判定、`--force-with-lease` のブランチ判定）だけを残す方針です。ガードを変更したら `python3 .claude/hooks/tests/test_guard.py` で回帰を確認すること。

## agentcore/cdk

生成物のため編集不可（`@AGENTS.md` 参照）。コマンドは `npm run build` / `npm test`（jest）/ `npm run format`。

CI は build/test を除外中 — 原因は `@aws/agentcore-cdk` (alpha) ではなく `lib/cdk-stack.ts` の `connectorName`（正しくは `connector`）というプロパティ名の不一致。

## Vetting new Claude Code skills/plugins before adding them

Before adding a new skill or plugin to this project (via `claude plugin install` or `npx skills add`), scan it first with [SkillSpector](https://github.com/NVIDIA/SkillSpector) — declared as a project-scoped MCP server (`skillspector`) in `.mcp.json`, exposing a `scan_skill` tool.

- The MCP server requires the `skillspector` CLI to be installed locally first (one-time, per machine): `uv tool install --python 3.12 'skillspector[mcp] @ git+https://github.com/NVIDIA/skillspector.git'`. The `.mcp.json` declaration is git-shared, but — like plugins — the binary itself is not; each contributor installs it once.
- Static-only scans (no `ANTHROPIC_API_KEY`/LLM configured) produce meaningful false positives, especially on skills that themselves contain pattern-detection logic (e.g. a design-antipattern linter's own signature strings get flagged as "prompt extraction"). Treat a CRITICAL/DO NOT INSTALL verdict from a static-only run as a lead to manually verify against the flagged source lines, not as a final answer — set `ANTHROPIC_API_KEY` to enable the semantic analyzers for a more reliable verdict.
